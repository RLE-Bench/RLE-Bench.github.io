A Qualifying Exam for Coding Agents
as Robot Learning Engineers

Not a puzzle set. Eight families of the work a robot learning engineer actually does — design a mobile manipulator from stock parts, co-design teleop hardware, learn a policy through a metered simulator, build a harness a stranger can use, estimate pose under adversarial sensing, ship a closed-loop controller, reason about physical structure, train a whole-body tracking pipeline. Each one is a real engineering problem handed to the agent inside a container, and each one is graded by a verifier the agent never sees.

Data and scope

Illustrative snapshot. The model scores, API costs, and agent times shown here are development placeholders. They are not empirical performance claims. Task metadata and supplied aggregation rules are retained from the existing implementation.

This homepage retains the eight-family, 64-instance leaderboard configuration. The research blog describes the manuscript’s separate task taxonomy and reported-results snapshot; its numerical results must not be interpreted as equivalent to this leaderboard.

Per-family costs are estimates based on a fixed share of each agent’s total suite cost, not independently metered family-level expenditure. Reward components and calibration notes are available under each task.
